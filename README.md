# Архив сайтов (Yandex Cloud, без сервера)

Сайт-архив для статических сайтов. Загружаете HTML-файл или ZIP-архив с сайтом целиком (стили, картинки, скрипты) — он сохраняется и становится доступен по постоянной ссылке. Смотреть может кто угодно, загружать — только тот, кто знает пароль (25 символов).

Постоянно работающего сервера нет — всё построено на сервисах Yandex Cloud, за которые платите только за использование:

```
 Браузер ──► бакет «<имя>»          интерфейс архива (index.html, app.js…)
    │
    ├──► Cloud Function «<имя>-api»  проверяет пароль, выдаёт подписанные ссылки
    │
    └──► бакет «<имя>-sites»         сами сайты: s/<id>/…  и список index.json
```

1. Браузер сам распаковывает ZIP и отправляет функции список файлов вместе с паролем.
2. Функция проверяет пароль и возвращает подписанные ссылки — по ним браузер загружает файлы **прямо в Object Storage** (поэтому нет ограничения 3,5 МБ на запрос функции).
3. Функция проверяет, что все файлы на месте, и добавляет сайт в `index.json`.

Сайты открываются с отдельного адреса (`<имя>-sites.website.yandexcloud.net`), поэтому их скрипты не могут прочитать пароль, сохранённый в браузере на странице архива.

## Сколько стоит

При личном использовании — обычно несколько рублей или десятков рублей в месяц: хранение в Object Storage (≈2–3 ₽ за ГБ в месяц), запросы и исходящий трафик, вызовы функции (первый миллион в месяц бесплатный). Новым аккаунтам Yandex Cloud даёт стартовый грант. Актуальные цены — в калькуляторе на yandex.cloud.

## Развёртывание скриптом

Нужны: [Yandex Cloud CLI](https://yandex.cloud/ru/docs/cli/quickstart) (`yc init` выполнен, выбран каталог), `curl`, `zip`, `jq`, Node.js (для `npm install`).

```bash
cd function && npm ci && cd ..          # нужен только для package-lock.json
UPLOAD_PASSWORD='ваш-пароль-из-25-символов' ./deploy.sh my-archive
```

Скрипт создаст бакеты `my-archive` и `my-archive-sites`, сервисный аккаунт, секрет в Lockbox, функцию и загрузит интерфейс. В конце напечатает адрес архива — `https://my-archive.website.yandexcloud.net`.

- Имя должно быть уникальным во всём Yandex Cloud (это имя бакета): только строчные латинские буквы, цифры и дефис.
- Ключи и пароль сохраняются в `.deploy-my-archive.json` — не публикуйте этот файл (он в `.gitignore`).
- Чтобы обновить код после изменений, просто запустите скрипт ещё раз.

## Развёртывание вручную через консоль

1. **Бакет для сайтов** `my-archive-sites`: Object Storage → Создать бакет → доступ на чтение объектов — *Публичный*. Затем в бакете:
   - *Веб-сайт* → Хостинг, главная страница `index.html`;
   - *CORS* → правило: Origins `https://my-archive.website.yandexcloud.net`, методы `GET, PUT, HEAD`, Allowed headers `*`.
2. **Бакет для интерфейса** `my-archive`: так же публичный, *Веб-сайт* → Хостинг, главная `index.html`.
3. **Сервисный аккаунт** `my-archive-fn` с ролями `storage.editor` и `lockbox.payloadViewer` на каталог. В нём создайте *статический ключ доступа*.
4. **Lockbox** → секрет `my-archive-secrets` с ключами `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY` (из шага 3) и `UPLOAD_PASSWORD` (ровно 25 символов).
5. **Cloud Functions** → создать функцию `my-archive-api`, сделать *публичной*. Новая версия:
   - среда выполнения Node.js 22, точка входа `index.handler`, память 256 МБ, таймаут 30 с;
   - код — ZIP из файлов папки `function/` (`index.js`, `handler.js`, `s3storage.js`, `package.json`, `package-lock.json`);
   - сервисный аккаунт `my-archive-fn`;
   - переменные окружения: `SITES_BUCKET=my-archive-sites`, `UI_ORIGIN=https://my-archive.website.yandexcloud.net`;
   - секреты Lockbox: три ключа из шага 4 в одноимённые переменные окружения.
6. В `public/config.js` впишите `apiUrl` (ссылка на функцию, `https://functions.yandexcloud.net/<id>`) и `sitesUrl` (`https://my-archive-sites.website.yandexcloud.net`). Загрузите все файлы из `public/` в бакет `my-archive`.

## Как пользоваться

- Откройте адрес архива, введите пароль (можно поставить «Запомнить в этом браузере»), перетащите `.html` или `.zip` и нажмите «Сохранить в архив».
- В ZIP главной страницей станет `index.html` (или первый HTML-файл); общая папка внутри архива убирается автоматически.
- Удалить сайт можно из браузера, откуда он загружен, или из любого браузера, если введён пароль.
- Если список на главной разошёлся с содержимым бакета, его можно пересобрать: POST на функцию с телом `{"action":"reindex","password":"…"}`.

## Локальная разработка

```bash
npm run dev     # эмулятор: интерфейс на :3000, «бакет с сайтами» на :3001, пароль печатается в консоль
npm test        # тесты логики функции
```

Своё доменное имя можно подключить к бакетам через Certificate Manager и CNAME — см. документацию Object Storage «Собственный домен».
